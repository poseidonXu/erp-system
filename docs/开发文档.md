# 华晟 ERP 系统 · 开发文档

> 基于《ERP系统需求规格说明书（模拟样例）》实现的教学演示型 ERP 系统
> 技术栈：Python Flask + HighGo 数据库（PostgreSQL 10.6 兼容）+ 原生 JavaScript 前端
> 开发工具：Visual Studio Code

---

## 1. 项目概述

### 1.1 建设目标
针对需求说明书中"华晟机械制造有限公司（模拟）"的业务痛点（数据分散、库存不准、计划困难、交付不透明、核算滞后），实现一套覆盖核心业务闭环的轻量 ERP 系统，打通：

```
销售订单 → MRP 运算 → 采购/生产 → 入库 → 发货 → 应收应付 → 报表
```

### 1.2 本期实现范围
对照需求说明书第 4 章的 P1（必须实现）功能，本系统实现了：

| 模块 | 编号 | 已实现功能 |
|------|------|-----------|
| 基础数据 M01 | F01-01~05 | 物料、BOM、客户、供应商、仓库库位 |
| 采购管理 M02 | F02-01/03/04 | 采购申请(由MRP建议)、采购订单、到货入库、应付联动 |
| 库存管理 M03 | F03-01/04/06 | 出入库、盘点、库存台账/分类账、预警 |
| 销售管理 M04 | F04-02/03/05 | 销售订单(信用校验)、发货出库、回款核销 |
| 生产管理 M05 | F05-01~05 | MPS、MRP 运算、生产工单、领料、完工入库 |
| 财务管理 M06 | F06-01/02/04 | 应付、应收、凭证生成与导出 |
| 报表中心 M07 | 各 P1 报表 | 经营看板 + 7 张查询报表 + CSV 导出 |
| 系统管理 M08 | F08-01/02/04 | 用户、角色、操作日志、参数 |

**未实现（P2/P3 及二期）**：询价比价、批次先进先出、调拨审批流、成本核算完整模型、质量/HR 模块、外部接口对接。

## 2. 设计思路（参考开源 ERP）

本项目借鉴了主流开源 ERP 的成熟设计思想：

### 2.1 Odoo —— 模块化应用架构
- 每个业务域作为独立模块（蓝图 Blueprint），通过统一的数据库层解耦；
- 单据采用**状态机**驱动：`draft（草稿）→ confirmed（确认）→ partial（部分）→ done（完成）`，状态决定可执行操作；
- 主数据（物料/客户/供应商）统一编码、全系统引用 ID。

### 2.2 ERPNext —— 库存分类账（Stock Ledger）
- 所有库存变动**不直接改结存数字**，而是先写一条不可变的 `stock_ledger` 流水（正数为入、负数为出，带来源单据号），再回写 `stock_balance` 结存；
- 这样每一笔库存都能向上追溯到来源单据（采购入库单/发货单/领料单/盘点单），真正实现"账实相符、全程可追溯"；
- 出库时对多个结存行按先进先出（FIFO）扣减。

### 2.3 移动加权平均计价
- 每次入库重算平均成本：`新均价 = (原数量×原均价 + 入库数量×入库单价) / 新数量`；
- 出库按当前均价结转成本，用于库存金额与完工成本统计。

3. **初始化数据库**（首次或需重置演示数据时）：`python database/init_db.py`
4. **启动服务**：
   - 方式 A：双击 `run.bat`

## 5. 数据库设计

### 5.1 分层
- **系统域**：`department`、`sys_user`、`operation_log`、`sys_param`
- **主数据域**：`material`、`customer`、`supplier`、`warehouse`、`location`、`bom`、`bom_item`
- **库存域**：`stock_balance`（结存）、`stock_ledger`（分类账）、`stock_transfer`、`stock_count`
- **业务单据域**：`purchase_order`/`purchase_order_item`、`sales_order`/`sales_order_item`、`payment_received`、`mps`、`mrp_result`、`work_order`、`material_issue`
- **财务域**：`account_payable`、`payment_paid`、`voucher_export`
- **报表视图**：`v_stock`、`v_po_exec`、`v_so_exec`、`v_finance`

### 5.2 关键表说明

**stock_ledger（库存分类账，核心表）**

| 字段 | 说明 |
|------|------|
| txn_no | 流水号（唯一） |
| doc_type | 单据类型：采购入库/生产入库/销售出库/领料出库/调拨/盘盈/盘亏 |
| doc_no | 来源单据号（可追溯） |
| qty | 数量（绝对值） |
| direction | IN / OUT |
| cost | 单位成本 |

**purchase_order / sales_order（单据状态机）**
-采购：`draft → confirmed → partial → received`，`cancelled`
-销售：`draft → confirmed → partial → shipped`，`cancelled`

### 5.3 兼容性处理（HighGo / PG10.6）
初版使用了 PG12+ 特性，已针对 PG10.6 修正：
- 生成列 `GENERATED ALWAYS AS ... STORED` → 改为应用层计算（`amount`、`diff_qty` 字段）；
- 触发器 `EXECUTE FUNCTION` → 改为 `EXECUTE PROCEDURE`（PG11+ 才支持 FUNCTION 关键字）。

## 6. 核心实现

### 6.1 库存记账 `post_stock()`（backend/db.py）
所有出入库的唯一入口，接收 `qty`（正入负出），在同一数据库事务内：
1. 写一条 `stock_ledger` 流水；
2. 入库：按"物料+仓库+库位+批次"定位结存行，重算移动加权平均成本；
3. 出库：跨结存行按 id 升序（FIFO）扣减，库存不足则抛出 `ValueError` 回滚整个事务。

业务函数（如 `receive_po`、`ship_so`）调用它后，继续写应付/应收/凭证，**全部在同一事务**——保证"单据、库存、财务"三者一致。

### 6.2 MRP 运算（backend/routes/production.py）
```
对每张待运算 MPS：
  按 BOM 逐层展开（最多 5 层）：
    毛需求 = 上层需求 × 单位用量 × (1 + 损耗率)
    可用量 = 现有库存 + 在途采购(已确认未入库) + 在制工单(未完工)
    净需求 = max(0, 毛需求 - 可用量)
    子件若自身有 BOM → 建议 PRODUCE，否则 → 建议 PURCHASE
    对自制件递归展开下一层
```
运算结果存入 `mrp_result`，供报表展示与生成工单/采购单参考。

### 6.3 采购到货入库 `receive_po`
- 支持整单或按明细部分入库；
- 超交校验（入库量 ≤ 未交量）；
- 调用 `post_stock` 记采购入库账；
- 按入库金额生成 `account_payable` 应付；
- 生成"借:原材料 / 贷:应付账款"凭证数据。

### 6.4 销售发货 `ship_so`
- 确认时校验客户信用额度与库存可用性；
- 发货时按移动平均成本结转，扣减库存；
- 生成应收（通过订单 shipped_amt 体现）与"借:应收账款 / 贷:主营业务收入"凭证。

### 删除单条记录的交互与健壮性

前端统一使用 `confirmDelete()`（见 `js/app.js`）替代浏览器原生 `confirm`：

- 弹窗展示**删除对象的编码与名称**，避免误删；红色「确认删除」按钮标识危险操作；
- 点击后按钮变为「删除中…」并禁用，防止重复提交；失败时保留弹窗并提示错误，可重试；
- 删除成功后自动刷新下拉缓存（`preload`），避免表单仍引用已删除记录；
- 若删除因「已被引用」失败（`code=3`），弹窗内会显示原因并出现「改为停用」按钮，一键切换 `enabled` 状态——这是被引用记录的正规处理方式（停用后不再参与新业务，但历史单据仍可查看）。基础数据列表同时提供「停用/启用」按钮和状态徽章。

后端删除接口做了三层防护（`backend/routes/base_data.py`）：

1. **存在性校验**：记录不存在返回 `code=404`，不再误报"删除成功"；
2. **引用校验**：被业务单据引用的记录返回 `code=3`，提示改用「停用」；
3. **审计日志**：成功删除写入 `operation_log`，含操作人、资源、编码与 ID。

## 8. VSCode 开发指南

1. 用 VSCode 打开 `erp-system` 文件夹；右下角提示安装推荐插件时点击"安装"（Python 扩展）。

## 9. 验证记录

开发过程中完成了完整的端到端验证（所有环节返回 code=0）：

```
登录 → 基础数据查询 → 采购订单(建→确认→入库) → 应付生成 → 凭证生成
→ 销售订单(建→确认→发货→收款) → MPS → MRP(4条净需求)
→ 工单(建→下达→领料4条明细→完工入库) → 库存结存更新 → 报表/看板
```

验证时修复的问题：
- PG10.6 不支持生成列 / `EXECUTE FUNCTION` 语法（已改为应用层计算 / `EXECUTE PROCEDURE`）；
- 出库未按库位匹配结存行导致"库存不足"（改为跨库位 FIFO 扣减）；
- 领料明细单号重复违反唯一约束（改为每条明细独立单号）。

## 10. 后续扩展建议

- **安全**：密码由 sha256 升级为 bcrypt；增加 JWT 鉴权与按角色的接口级权限拦截；敏感字段脱敏。
- **业务**：补齐 P2 功能（询价比价、调拨审批、批次 FIFO、完整成本核算）。
- **性能**：为高频查询字段加索引；列表分页；报表改为物化视图或异步任务。
- **部署**：改用 gunicorn/waitress + Nginx；数据库定期备份；HighGo 服务设为开机自启。
- **接口**：按需求第 7 章预留财务系统凭证导入、OA 审批回调、PDA 条码接口。
